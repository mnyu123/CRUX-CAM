# Phase 3 크롭·MP4 내보내기

## 사용 순서

1. 분석 화면에서 사람을 선택하고 **크롭 미리보기**를 엽니다.
2. 비율을 고릅니다. **3:4는 가로 3, 세로 4**입니다. 세로 9:16, 가로 16:9, 4:5, 1:1, 원본 비율도 제공합니다.
3. 영상 바로 아래에서 확대 1.0~2.5배를 조절합니다. 원본에서 영역 보기를 켜면 영역을 드래그할 수 있습니다. 좌우·상하 슬라이더도 같은 위치를 조절하며 초기화 버튼은 확대·위치를 초기화합니다.
4. 출력 화질과 원본 소리 유지 여부를 정하고 **MP4 내보내기**를 누릅니다. 진행률과 취소 버튼을 제공합니다. 완료까지 앱을 열어두세요.
5. 완료 후 갤러리에 저장하며 **내보낸 영상 확인**에서 재생합니다. 저장 권한 거부·저장 위치 선택 취소·저장 실패 시 완성본은 앱에 남고 **갤러리 / 파일에 저장**으로 재시도할 수 있습니다.

위치 조절은 자동 추적 위치에서 전체 영상에 같은 이동량을 더합니다. 특정 시간만 편집하는 키프레임 도구는 아닙니다. 기본값은 관절 주변에 여유를 두지만 큰 확대나 넓은 비율에서는 손발이 잘릴 수 있습니다. 원본에 없는 세부 정보를 확대해서 복원하지 않습니다.

가로 화면에서는 영상·컨트롤과 설정을 좌우로 배치합니다. 내보내는 동안 설정·재생 조작을 잠그며 화면 종료·앱 백그라운드 이동 시 인코딩을 취소합니다. 사진은 크롭 미리보기·JSON 저장만 제공합니다.

## 크롭 경로

`CropPlanner`가 선택한 사람의 보정 관절 범위에 여유를 두고 출력 비율에 맞춘 영역을 만듭니다. 위치 보정은 원본 화면 기준 -50%~+50%이며 모든 영역을 영상 안으로 제한합니다. 빠른 움직임은 빨리 따라가고 축소는 확대보다 빠르게 적용합니다.

연속 추적 구간은 선형 보간합니다. 대상 누락 구간은 마지막 영역을 유지하며 최초 감지 전에는 가능한 넓은 영역을 표시합니다. 다른 번호의 사람을 따라가지 않습니다. 두 OS의 렌더러도 같은 보간·누락 정책을 사용합니다.

`crop_<시간>.json`을 분석 저장 폴더에 저장합니다. schemaVersion 1, kind=crop_timeline, sourceName, 분석 이미지 크기, durationMs, personId, engine, ratio/zoom/smooth/offsetX/offsetY와 프레임별 timeMs/rect/status를 기록합니다. rect는 `[left, top, width, height]`이며 회전 적용 후 원본 전체 화면 기준 0~1 좌표입니다. 분석용 축소 이미지 대신 원본 영상에 이 좌표를 적용합니다. 계산·JSON 변환은 별도 실행 공간에서 처리하고 이전 설정의 늦은 결과는 버립니다.

## 출력과 플랫폼

| 항목 | 정책 |
| --- | --- |
| 기본 파일 | MP4 컨테이너, H.264/AVC 영상, 소리가 있으면 AAC |
| 화질 | 기본: 짧은 변 최대 720px / 높음: 최대 1080px. 원본보다 짧은 변을 키우지 않고 짝수 크기로 반올림 |
| 프레임 | 관절 분석의 2/5/10fps로 낮추지 않고 원본 프레임 시간 사용 |
| 소리 | 기본 유지, 선택 시 제거. 소리 없는 원본도 변환 가능 |
| 공간 | 출력·갤러리 복사 예상 용량과 여유 공간을 확인. 실제 용량은 예상과 다를 수 있음 |
| 취소·오류 | 불완전한 작업 파일만 정리. 완료 파일은 확인 후 이름을 바꾸고 원본은 수정·삭제하지 않음 |
| HDR | H.264 출력에 맞춰 SDR 변환. 다양한 HDR 영상·기기는 추가 검증 필요 |

Android는 재생 플러그인과 같은 Media3 **1.9.2** Transformer/effect를 사용합니다. 시간에 따른 OpenGL 행렬로 크롭하며 H.264·AAC를 요청하고 출력 코덱·방향·해상도·길이·소리를 다시 확인합니다. 미지원 해상도·인코더를 임의로 바꾸지 않고 실패를 안내합니다. 기본 6Mbps / 높음 12Mbps를 요청하며 실제 비트레이트는 기기가 결정합니다.

Android 10 이상은 넓은 저장소 권한 없이 MediaStore의 `Movies/CRUX-CAM`에 저장합니다. 복사를 마친 후 갤러리에 공개하며 실패하면 이 작업이 만든 등록 행을 제거합니다. Android 7~9는 시스템 저장창에서 사용자가 고른 위치에 저장합니다.

iOS는 AVFoundation·Core Image로 같은 경로를 적용하고 `AVAssetExportPresetHighestQuality`로 MP4·H.264·AAC를 생성합니다. 크기·프레임 간격을 지정하며 비트레이트는 Apple 인코더가 결정합니다. 사진 **추가 권한**으로 Photos에 저장하며 거부하면 앱의 완성본을 유지합니다. 구현은 `phase2-ios`에 있으며 Windows에서는 실제 iOS 빌드·인코딩 검증이 불가능하므로 Mac에서 확인해야 합니다.

기술 근거: [Media3 Transformer](https://developer.android.com/media/media3/transformer/getting-started), [프레임 변환](https://developer.android.com/reference/androidx/media3/effect/GlMatrixTransformation), [Apple H.264 프리셋](https://developer.apple.com/documentation/avfoundation/avassetexportpresethighestquality), [Core Image 영상 처리](https://developer.apple.com/documentation/avfoundation/avvideocomposition/init(asset:applyingcifilterswithhandler:)). Instagram 도움말은 이번 조회에서 접근되지 않아 영상 게시 규격의 보장으로 표시하지 않습니다. 3:4는 사용자가 요청한 세로 비율입니다.

## 검증과 후속 범위

`flutter analyze`, `flutter test`로 정적 분석·공통 테스트를 실행합니다. 크롭 경계·비율·보간·누락·위치 보정·초기화, 내보내기 기본값, 준비 중 취소·종료, 저장 권한 거부·재시도, 인코더 실패 후 재시도와 접근성 트리를 확인합니다.

```powershell
flutter test integration_test/export_test.dart -d emulator-5554
```

직접 만든 네 가지 색·소리 포함 4초 영상으로 실제 MP4·3:4·시간별 크롭 위치·회전·소리 유지/제거·재생·갤러리 저장·취소와 결과 화면 왕복을 검증합니다. iOS는 최초 사진 추가 권한 팝업을 허용해야 갤러리 저장 검증을 진행할 수 있습니다.

개인 클라이밍 영상은 기존 `scripts/android_phase2.ps1 -Action visual`로 분석→사람 선택→3:4 내보내기→갤러리 저장→12초 결과 재생을 확인합니다. 영상은 테스트에만 임시 포함하고 pubspec을 복구합니다. 개인 영상·캡처·좌표·빌드 파일은 Git에 포함하지 않으며 테스트 후 일반 APK를 다시 빌드·설치합니다.

후속: H.265 선택, 4K·백그라운드 내보내기, 시간별 수동 크롭, 트림/영상 합치기, 결과 목록·불러오기, 사진 파일 내보내기. 다른 기기·HDR·가변 프레임 영상과 iOS 실기기 검증은 추가로 필요합니다.
